# Attack-Specific Feature Signatures in NIDS — Code & Data Availability

This repository accompanies the paper *"Attack-Specific Feature Signatures in Network Intrusion Detection: A Cross-Dataset Explainability Analysis"* (submitted to *Computers & Security*). It contains the preprocessing scripts, SHAP signature extraction code, and analysis code referenced in the paper's **Data Availability** statement:

> *"The NFv2 datasets are publicly available at http://staff.itee.uq.edu.au/marius/NIDS_datasets/ [12]. Preprocessing scripts, SHAP signature extraction code, and analysis code are available at [this repository]."*

**Note on the three "superseded" scripts** (`analysis2_shap_guided_transfer.py`,
`analysis3c_signature_stability.py`, `plot_paper_figures.py`): these were early
versions later replaced by a corrected/improved version (`analysis3`,
`analysis3c_signature_stability_v2.py`, `plot_paper_figures_v2.py`
respectively). They are included for provenance/transparency but their
outputs are **not** the ones cited in the paper — use the official scripts
listed above them.

**Note on cross-script imports**: `analysis3c_signature_stability.py` /
`analysis3c_signature_stability_v2.py` import `analysis3b_nested_target10.py`
as a module, and `analysis5b_random_direct.py` imports
`analysis5_shap_direct_transfer.py` as a module. All four files must stay in
the same directory (`code/`) for this to work — do not move them into
separate subfolders.

## Raw data

The four NetFlow v2 (NFv2) benchmark datasets used in this study
(NF-UNSW-NB15-v2, NF-BoT-IoT-v2, NF-CSE-CIC-IDS2018-v2, NF-ToN-IoT-v2) are
**not redistributed in this repository** — they are large (2–6 GB each, ~12
GB total) and already publicly hosted by their original authors:

> https://staff.itee.uq.edu.au/marius/NIDS_datasets/

Download the four `NF-*-v2.csv` files and place each one at
`<dataset-name>/data/<dataset-name>.csv`, e.g.:

```
NF-UNSW-NB15-v2/data/NF-UNSW-NB15-v2.csv
NF-BoT-IoT-v2/data/NF-BoT-IoT-v2.csv
NF-CSE-CIC-IDS2018-v2/data/NF-CSE-CIC-IDS2018-v2.csv
NF-ToN-IoT-v2/data/NF-ToN-IoT-v2.csv
```

`NF-UNSW-NB15-v2/data/NetFlow_v2_Features.csv` (the shared 40-feature schema
reference, ~2 KB, identical across all four datasets) is already included
here for convenience.

## Processed data

`preprocess_nfv2.py` reads a raw dataset CSV, applies the shared 40-feature
schema, excludes low-sample classes, stratified-samples down to a 2,000,000-row
cap, and writes `processed/<dataset>_processed.csv` +
`processed/<dataset>_feature_cols.txt`. This repository ships the `processed/`
directory **empty**: the four processed CSVs total ~1.1 GB (individual files
up to ~350 MB), which exceeds typical code-hosting limits (e.g., GitHub's
100 MB per-file hard limit) and is not required by the paper's Data
Availability statement — it is fully regenerable from the public raw data via
`preprocess_nfv2.py`. If your target host supports large files (e.g., Zenodo,
OSF), the processed CSVs can be added here separately.

## Environment

Two equivalent ways to set up the environment:

```bash
# Option A — use the provided setup script (creates .venv/)
bash setup_env.sh
source .venv/bin/activate

# Option B — install from requirements.txt directly
pip install -r requirements.txt
```

**Note**: `shap` and `xgboost` require Python ≥3.10. All experiment scripts
in `code/` were run under Python 3.11.

## Reproduction pipeline

Run all commands from this directory (`upload/`) so the scripts' relative
`./processed/`, `./results/...` paths resolve correctly.

```bash
# 1. Preprocess all four raw datasets → processed/
bash code/batch_preprocess.sh
#    (equivalent to running, per dataset:)
#    python code/preprocess_nfv2.py --data ./NF-UNSW-NB15-v2/data/NF-UNSW-NB15-v2.csv

# 2. RQ1 — per-class SHAP signature extraction (once per dataset) → results/rq1/
python code/shap_signatures_rq1.py --data ./processed/NF-UNSW-NB15-v2_processed.csv --out ./results/rq1/
#    (repeat for NF-BoT-IoT-v2, NF-CSE-CIC-IDS2018-v2, NF-ToN-IoT-v2)

# 3. RQ2 — cross-dataset signature transferability → results/rq2/
python code/shap_analysis_rq2.py --rq1-dir ./results/rq1/ --out ./results/rq2/

# 4. Intra-dataset signature distinctiveness (Table IV) → results/analysis1/
python code/analysis1_intraset_distinctiveness.py --rq1-dir ./results/rq1/ --out ./results/analysis1/

# 5. RQ3 core — nested Target-10 within-dataset (Table VI-a) → results/analysis3b/
python code/analysis3b_nested_target10.py --data-dir ./processed/ --out ./results/analysis3b/ --n-seeds 30

# 6. RQ3 core — 30-seed SHAP-10 vs Random-10 cross-dataset transfer (Table VI-b) → results/analysis3/
python code/analysis3_statistical_validation.py --rq1-dir ./results/rq1/ --data-dir ./processed/ --out ./results/analysis3/ --n-seeds 30

# 7. Signature cross-seed stability (§3.2.4/4.1.4) → results/analysis3c_v2/
python code/analysis3c_signature_stability_v2.py --data-dir ./processed/ --out ./results/analysis3c_v2/ --n-seeds 30

# 8. JSD behavioral-distance analysis (Fig. 10) → results/analysis4/
python code/analysis4_jsd_behavioral_similarity.py --data-dir ./processed/ --out ./results/analysis4/

# 9. Zero-shot model transfer: SHAP-10-Direct (Table VII, Fig. 11) → results/analysis5/
python code/analysis5_shap_direct_transfer.py --rq1-dir ./results/rq1/ --data-dir ./processed/ --out ./results/analysis5/ --n-seeds 30

# 10. Zero-shot baseline: Random-10-Direct (Table VII) → results/analysis5b/
python code/analysis5b_random_direct.py --rq1-dir ./results/rq1/ --data-dir ./processed/ --out ./results/analysis5b/ --n-seeds 30

# 11. Final statistical checklist / Table VII assembly → results/analysis6/
python code/analysis6_finalize_checklist.py --rq2-dir ./results/rq2/ --analysis3-dir ./results/analysis3/ --analysis4-dir ./results/analysis4/ --analysis5-dir ./results/analysis5/ --out ./results/analysis6/

# 12. Regenerate Fig. 9 (environment-similarity vs. transfer performance)
python code/regen_fig9_env_correlation.py

# 13. Generate Fig. 1–5 → results/figures_v2/
python code/plot_paper_figures_v2.py --rq1-dir ./results/rq1/ --rq2-dir ./results/rq2/
```

Exact CLI flags (defaults, optional arguments such as `--classes`,
`--topk`, `--skip-dup-check`) are documented in each script's own
module docstring and `argparse` definitions — run any script with `--help`
for the full option list.

## Verifying against the paper's reported numbers

`results/` in this repository already contains the exact output files that
back every number cited in the paper's tables and figures (e.g.
`results/analysis3/analysis3_raw_results.csv` underlies Table VI-b,
`results/analysis5/analysis5_raw_results.csv` + `results/analysis5b/` underlie
Table VII). Re-running the pipeline above should reproduce these files
byte-for-byte for the deterministic steps, and statistically identically
(same seeds 42–71) for the stochastic ones.
